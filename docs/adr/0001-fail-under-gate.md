# ADR-0001: 评测回归门禁——作用于主管线，退出码三态

- 状态：已采纳
- 日期：2026-10-02（成文 2026-10-04，追溯既有决策）
- 关联代码：`src/llm_eval_kit/gates.py`、`src/llm_eval_kit/cli.py`、`.github/workflows/pages.yml`

## 背景

评测工具的常见用法是"跑一次、看一眼"，指标回退只能靠人眼发现。
要让评测结果真正约束交付（如 Pages 报告发布、下游 RAG 的检索改造），需要机器可判定的门禁：
`--fail-under 指标=阈值`。随之而来的口径问题：多管线对比时门禁管谁？
参数错误和指标不达标如何区分？

## 决策

1. 门禁只作用于**主管线**（第一个注册的检索管线）。多管线对比是分析用途，
   让所有管线都过同一阈值会把"对照组"也卡进闸门，语义混乱。
2. 退出码三态：达标 0 / 指标不达标 1 / 参数错误（未知指标、非法阈值、
   `--dataset` 与 `--num-cases` 等互斥冲突）2。脚本可以区分"评测退化了"
   和"调用方式错了"这两种完全不同的失败。
3. 不达标时 stderr 输出实测值、阈值与差距三项，不输出乐观摘要。

## 代价

- 对比新管线时门禁不覆盖非主管线；需要回归保护的新管线应注册为主管线。
- Pages workflow 直接 `--fail-under` 后不达标不发布报告——报告"缺失"本身就是告警信号，
  这是接受的语义。
