# ADR-0001：放弃"LLM 生成代码 + 沙箱执行"，改用方法白名单 + 确定性分派

- 状态：已采纳
- 日期：2026-09-30
- 关联：PROJECT_BRIEF.md 早期版本（Phase 1 "受控 Python 执行" 承诺）

## 背景

立项时（PROJECT_BRIEF 原稿）计划的执行层是业界常见方案：LLM 阅读数据画像后生成
pandas/scipy 分析代码，平台在受限子进程（白名单库 + 资源限制）里执行，Phase 2 升级为
Docker 沙箱。这也是"AI 数据分析 Agent"赛道的主流做法。

## 决策

执行层改为**方法白名单 + 确定性分派**：

1. LLM 只产出结构化**实验计划**（方法名 + 变量 + 假设 + α），不产出代码；
2. 方法必须在白名单内（与执行层单一来源：`services.executor.RUNNER_METHODS`），
   且方法-变量类型组合通过 `method_fits_types` 校验，不符则按规则降级并留痕；
3. 每个白名单方法对应一段人工编写、经测试覆盖的 scipy 调用（`services/executor.py`）；
4. 所有统计数字由这些固定实现真实计算，LLM 只负责生成计划与解释结果；
5. 每个实验附可独立运行的 scipy 复现脚本（`services/repro.py`），替代"回放生成代码"。

## 理由

- **安全边界前移**：任意代码生成的安全问题是运行时的、无止境的（沙箱逃逸、资源攻击、
  依赖投毒）；白名单把问题收敛为"计划是否合法"，在类型与词法层就能判定。
- **正确性可审计**：生成代码的正确性无法穷举测试，白名单方法的实现可以（124+ 用例）。
- **可复现性更强**：固定的 scipy 调用 + 原始 p 值入库 + 复现脚本，比"回放 LLM 曾生成
  的代码"更符合科研规范。
- **诚实性**：计划来源（llm/rule）、方法校正理由、解读来源全部留痕可查。

## 代价

- 放弃了任意表达力：LLM 无法组合出白名单之外的分析（例如自定义变换）。
- 每个 新方法需要人工实现与测试；扩展速度受工程节奏限制。

## 后续

若未来需要真正任意的代码执行（Phase 2+ 的 ML 自动化），在 Docker 沙箱内进行，
且生成的代码只允许调用本项目审计过的工具库，不接触原始解释器能力。
